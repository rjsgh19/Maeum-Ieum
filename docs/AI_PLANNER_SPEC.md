# AI Planner 산출물 스펙

구현에 들어가기 전, AI는 아래 **섹션 순서**로 Planner 결과를 채운다.  
채팅에 출력하거나 `docs/plans/YYYYMMDD_feature-name.md` 같은 파일로 저장해도 된다.

---

## P1. 한 줄 요약

- 무엇을, 누구를 위해, 어떤 결과로 바꾸는가 (1~2문장).

## P2. 배경·동기

- 왜 지금 필요한지, 관련 이슈·피드백이 있으면 요약.

## P3. 목표 (측정 가능할수록 좋음)

- 예: "리포트 로딩 시 N+1 쿼리 제거", "모바일에서 버튼 영역 44px 이상".

## P4. 범위

### 포함 (In scope)

- bullet 목록.

### 제외 (Out of scope)

- 이번에 **하지 않는 것**을 명시 (범위 누수 방지).

## P5. 사용자 시나리오

1. **Given** … **When** … **Then** … 형식으로 1개 이상.
2. API/화면이면 **엔드포인트·화면 위치**를 대략 적는다.

## P6. 기술 설계 초안

### 백엔드

- 변경·추가할 엔드포인트, 요청/응답 스키마(필드명·타입), 에러 코드.

### 프론트엔드

- 수정할 파일(예: `static/index.html`), UI 동작, 상태·API 호출 흐름.

### DB·데이터

- 테이블/컬럼/인덱스 변경, 마이그레이션 필요 여부, 기존 데이터 호환.

### 환경·설정

- 새 환경 변수 이름(값은 넣지 않음), feature flag 여부.

## P7. 의존성·리스크

- 외부 API, 레이트 리밋, 롤백 난이도, 성능 이슈.

## P8. 수용 기준 (체크리스트)

- [ ] 항목들은 **TDD/수동 테스트**로 바로 옮길 수 있게 구체적으로 쓴다.

## P9. 작업 분해 (선택)

- 커밋 단위 혹은 PR 단위로 쪼갠 순서.

---

Planner가 끝나면 사용자에게 **한 번 확인**할지 여부는 요청 성격에 따르되,  
모호한 요구(보안·결제·개인정보)는 **반드시 가정을 명시**한 뒤 진행한다.
